# `typeof` — eight answers, and the `null` that says object

**Level:** 101 · for anyone who has written a line of JavaScript

**One line:** `typeof` answers with one of eight strings, and two of its answers do not name the value's type: `typeof null` is `"object"` though no other test calls `null` an object, and a function or a class, which is an object, answers `"function"`; for a name nothing declares it answers `"undefined"`, yet it throws a `ReferenceError` for a `let` read before its line.

**Keywords:** `typeof`

`typeof` is an operator, written in front of a value, and its answer is always a string. The program asks it about one value of each of the [eight types](../eight_types/README.md), then about a function, an arrow function, an array, a class and an object the class built.

<!-- source:typeof_every_type_js -->
*[`typeof_every_type_js.js`](examples/typeof_every_type_js.js) in full — pasted here by `tools/run_examples.py` from the file CI runs.*

```javascript
// What typeof says about one value of each of the eight types, then about a
// function, an arrow function, an array, a class and an object the class built.
class Order {}

const samples = [
  ["undefined", undefined],
  ["null", null],
  ["true", true],
  ["42", 42],
  ["42n", 42n],
  ['"text"', "text"],
  ['Symbol("id")', Symbol("id")],
  ["{ id: 7 }", { id: 7 }],
  ["function total() {}", function total() {}],
  ["((price) => price)", (price) => price],
  ["[1999, 250]", [1999, 250]],
  ["Order", Order],
  ["new Order()", new Order()],
];

for (const [source, value] of samples) {
  console.log(`typeof ${source.padEnd(21)}${JSON.stringify(typeof value)}`);
}

const answers = [...new Set(samples.map(([, value]) => typeof value))];
console.log(`${answers.length} different answers: ${answers.join(", ")}`);
```

## Reading the output

- **Six types answer with their own name.** `undefined`, `true`, `42`, `42n`, `"text"` and `Symbol("id")` get `"undefined"`, `"boolean"`, `"number"`, `"bigint"`, `"string"` and `"symbol"`: the names of their types, in lower case.
- **`null` answers `"object"`.** Its type is Null, and it is a primitive — [Eight types](../eight_types/README.md) sorts it with the other six — but `typeof` has no answer `"null"` to give. The next section is about why.
- **An object answers `"object"` or `"function"`.** `{ id: 7 }`, the array and `new Order()` answer `"object"`; the function `total`, the arrow function and the class `Order` answer `"function"`. All six are of type Object, as [Eight types](../eight_types/README.md) shows with a test of its own. ECMA-262 decides between the two answers by asking whether the object can be called: an object with a `[[Call]]` internal method answers `"function"`, any other object `"object"` ([ECMA-262 — typeof: Evaluation ↗](https://tc39.es/ecma262/#sec-typeof-operator-runtime-semantics-evaluation)). A class has one, because a class is a function object ([Classes](../../07_Prototypes_and_Classes/classes_are_functions/README.md)).
- **An array is only `"object"`.** `typeof` cannot tell an array, a class instance and a plain object apart; the tests that can are under [How do you test for an array, for `null`, or for a plain object?](#how-do-you-test-for-an-array-for-null-or-for-a-plain-object)
- **Eight different answers.** The last line collects them. They are not one per type: Null has no answer of its own, and `"function"` is not the name of a type. In web browsers one object breaks the pattern the other way — `typeof document.all` is `"undefined"`, an exception the specification allows for web browsers ([MDN — typeof: document.all ↗](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Operators/typeof#exceptional_behavior_of_document.all)). *(Not machine-checked here: Node has no `document`.)*

## Why is `typeof null` `"object"`, and why will it stay that way?

The specification writes the answer down as a step of its own — *If value is null, return "object"* ([ECMA-262 — typeof: Evaluation ↗](https://tc39.es/ecma262/#sec-typeof-operator-runtime-semantics-evaluation)). No other way of asking agrees with it:

<!-- source:typeof_null_js -->
*[`typeof_null_js.js`](examples/typeof_null_js.js) in full — pasted here by `tools/run_examples.py` from the file CI runs.*

```javascript
// typeof calls null an object. Every other way of asking says it is not one.
const discount = null; // "no discount": a value some code chose to return

const rows = [
  ["typeof discount", JSON.stringify(typeof discount)],
  ["Object(discount) === discount", String(Object(discount) === discount)],
  ["discount instanceof Object", String(discount instanceof Object)],
  ["Object.prototype.toString.call(discount)", Object.prototype.toString.call(discount)],
];
try {
  rows.push(["discount.percent", String(discount.percent)]);
} catch (error) {
  rows.push(["discount.percent", `${error.name}: ${error.message}`]);
}

for (const [expression, result] of rows) {
  console.log(`${expression.padEnd(42)}${result}`);
}
```

*Verified output of [`typeof_null_js.js`](examples/typeof_null_js.js) — regenerated by `tools/run_examples.py`, never hand-typed.*

```text
typeof discount                           "object"
Object(discount) === discount             false
discount instanceof Object                false
Object.prototype.toString.call(discount)  [object Null]
discount.percent                          TypeError: Cannot read properties of null (reading 'percent')

<!-- /output -->

- **Only the first line says object.** `Object(discount) === discount` is `false`, the answer [Eight types](../eight_types/README.md) gets for every primitive; `discount instanceof Object` is `false`; `Object.prototype.toString` tags the value `[object Null]`; and reading a property from it throws a `TypeError`. By every other test, `null` is not an object.
- **Why it says object.** In the first implementation of JavaScript a value carried a type tag, and the tag for objects was 0; `null` was the null pointer, all zero bits, so it carried the object tag ([MDN — typeof: typeof null ↗](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Operators/typeof#typeof_null)).
- **Why it stays.** In 2011 a change to `typeof null === "null"` was proposed for code that opted in to the next edition of the language. V8 implemented it, it broke a lot of existing sites, and the proposal was rejected ([TC39 wiki, archived — harmony:typeof_null ↗](https://web.archive.org/web/20160331031419/http://wiki.ecmascript.org:80/doku.php?id=harmony:typeof_null), the page MDN cites). So `null` is tested with `=== null`, as [further down](#how-do-you-test-for-an-array-for-null-or-for-a-plain-object).

## Why does `typeof` not throw for an undeclared name, and when does it throw?

Reading a name that nothing declares throws a `ReferenceError`. `typeof` checks for that case before it reads anything: when the name resolves to nothing, the answer is `"undefined"` ([ECMA-262 — typeof: Evaluation ↗](https://tc39.es/ecma262/#sec-typeof-operator-runtime-semantics-evaluation)). The driver writes four small programs into a temporary folder and runs each with `node`, printing the program, what it printed, the error line and the exit status.

#!/usr/bin/env bash
# typeof on a name nothing declares, the same name handed to a helper function,
# and typeof on a let whose line has not run yet. Each program is written to a
# temporary folder and run by node; the driver prints the program, what it
# printed, the error line and the exit status.
set -u
work=$(mktemp -d)
trap 'rm -rf "$work"' EXIT
cd "$work" || exit 1

cat > bare.mjs <<'EOF'
console.log(window);
EOF

cat > guarded.mjs <<'EOF'
console.log(typeof window);
EOF

cat > helper.mjs <<'EOF'
const isDefined = (value) => typeof value !== "undefined";
console.log(isDefined(window));
EOF

cat > dead_zone.mjs <<'EOF'
console.log(typeof total);
let total = 0;
EOF

for program in bare.mjs guarded.mjs helper.mjs dead_zone.mjs; do
  [ "$program" = bare.mjs ] || echo
  echo "\$ cat $program"
  cat "$program"
  echo "\$ node $program"
  node "$program" 2> stderr.txt
  status=$?
  # Only the error's own line: the rest of stderr is a stack trace with paths.
  grep -E '^[A-Za-z]*Error' stderr.txt
  echo "exit status: $status"
done
```

<!-- /output -->

- **`bare.mjs`.** Node has no `window`, and nothing in the program declares one, so reading it throws `ReferenceError: window is not defined` and the program ends with exit status 1.
- **`guarded.mjs`.** The same name behind `typeof` prints `undefined`, and the program exits with 0. So `typeof window !== "undefined"` can ask whether a global exists at all without risking the error ([MDN — typeof: undeclared and uninitialized variables ↗](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Operators/typeof#interaction_with_undeclared_and_uninitialized_variables)).
- **`helper.mjs`.** Moving the check into a function does not work. The argument `window` is read before `isDefined` starts, and that read throws the same `ReferenceError`; `typeof` never sees the name. MDN makes the same point: a function of your own cannot copy this behaviour ([MDN — typeof: undeclared and uninitialized variables ↗](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Operators/typeof#interaction_with_undeclared_and_uninitialized_variables)).
- **`dead_zone.mjs`.** Here `total` is declared — by the `let` on the next line — so the name does resolve, and `typeof` goes on to read its value. A `let` has no value until its line has run, and reading it before then throws `ReferenceError: Cannot access 'total' before initialization`, under `typeof` or not. MDN lists `const` and `class` with `let` ([MDN — typeof: undeclared and uninitialized variables ↗](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Operators/typeof#interaction_with_undeclared_and_uninitialized_variables)); the stretch before the declaration is the temporal dead zone of [Hoisting and the temporal dead zone](../../04_Variables_and_Scope/hoisting_and_the_tdz/README.md).

## How do you test for an array, for `null`, or for a plain object?

`typeof` answers `"object"` for all six values below. Each column after it is another test.

<details markdown="1">
<summary>The program</summary>

<!-- source:typeof_other_tests_js -->
*[`typeof_other_tests_js.js`](examples/typeof_other_tests_js.js) in full — pasted here by `tools/run_examples.py` from the file CI runs.*

```javascript
// typeof says "object" for null, for an array and for every other kind of
// object. The tests below tell them apart; the last column is the old trick
// of asking Object.prototype.toString for a value's tag.
class Order {}

// A plain object is one made by {} or Object.create(null): its prototype is
// Object.prototype or nothing at all.
function isPlainObject(value) {
  if (value === null || typeof value !== "object") return false;
  const prototype = Object.getPrototypeOf(value);
  return prototype === Object.prototype || prototype === null;
}

const samples = [
  ["null", null],
  ["[1999, 250]", [1999, 250]],
  ["{ cents: 1999 }", { cents: 1999 }],
  ["Object.create(null)", Object.create(null)],
  ["new Order()", new Order()],
  ["new Date(0)", new Date(0)],
];

const columns = [
  ["typeof", (value) => JSON.stringify(typeof value), 10],
  ["=== null", (value) => String(value === null), 10],
  ["Array.isArray", (value) => String(Array.isArray(value)), 15],
  ["isPlainObject", (value) => String(isPlainObject(value)), 15],
  ["toString tag", (value) => Object.prototype.toString.call(value), 0],
];

console.log("value".padEnd(21) + columns.map(([name, , width]) => name.padEnd(width)).join(""));
for (const [label, value] of samples) {
  console.log(label.padEnd(21) + columns.map(([, test, width]) => test(value).padEnd(width)).join(""));
}
```

- **`typeof`** is `"object"` in every row, so it answers none of the three questions.
- **`null`: `value === null`.** It is `true` in the first row only. [`null` and `undefined`](../null_and_undefined/README.md) covers `value == null`, the test that lets `undefined` in as well.
- **An array: `Array.isArray(value)`.** It is `true` for the array only ([MDN — Array.isArray() ↗](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Array/isArray)). [Arrays](../../08_Arrays_and_Collections/array_basics/README.md) sets it beside `instanceof Array`.
- **A plain object: the program writes its own test.** `isPlainObject` starts with the usual guard — `value` is not `null` and `typeof value` is `"object"`, since `typeof` alone would let `null` through — then asks for the prototype: `Object.prototype` for `{ cents: 1999 }`, none at all for `Object.create(null)`. The class instance and the date have prototypes of their own, so they fail.
- **The toString tag** names `Null`, `Array` and `Date`, but it says `[object Object]` for a plain object and a class instance alike, so it cannot find a plain object; and an object can pick its own tag with `Symbol.toStringTag` ([MDN — Object.prototype.toString() ↗](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Object/toString)).

## What does TypeScript do with `typeof`?

`tsc` meets `typeof` in two places. In code, a `typeof` check narrows a variable's type inside the branch it guards. In a type annotation, `typeof` is a second operator with the same name, which reads the type `tsc` gave a variable. The program makes one mistake with each.

<!-- source:typeof_in_typescript_tserror -->
*[`typeof_in_typescript_tserror.ts`](examples/typeof_in_typescript_tserror.ts) in full — pasted here by `tools/run_examples.py` from the file CI runs.*

```typescript
// tsc reads typeof checks: after each one, the variable has a narrower type.
// It also knows that typeof null is "object", so null is still there after the
// third check.
function describe(reading: number | string | Date | null): string {
  if (typeof reading === "number") return reading.toFixed(1);
  if (typeof reading === "string") return reading.trim();
  if (typeof reading === "object") return reading.toISOString();
  return "no reading";
}

// In a type, typeof is a second operator with the same name: it reads the type
// tsc gave a variable, and it is erased before Node runs anything.
const station = { name: "north", celsius: 21.5 };
const next: typeof station = { name: "south", celsius: "22.0" };
```

- **Line 7, TS18047.** After the `"number"` and `"string"` checks, `reading` can only be a `Date` or `null`, and both answer `"object"`. So the third branch still holds `null`, and `tsc` refuses `reading.toISOString()`: `'reading' is possibly 'null'`. The checker knows the `null` row of the first table. The TypeScript handbook walks through the same trap ([TypeScript Handbook — typeof type guards ↗](https://www.typescriptlang.org/docs/handbook/2/narrowing.html#typeof-type-guards)), and [Narrowing](../../24_Narrowing/narrowing_by_control_flow/README.md) is the page for the other tests `tsc` narrows on.
- **Line 14, TS2322.** `typeof station` in the annotation means the type `tsc` inferred for `station`, and the note under the error spells it out: `{ name: string; celsius: number; }`. So the string `"22.0"` is refused for `celsius`. This `typeof` never runs — Node erases it with the rest of the annotation, as it erases every annotation ([How a page is checked](../../00_Start_Here/how_a_page_is_checked/README.md)). It has a page of its own, [`keyof` and `typeof` in types](../../27_Type_Operators/keyof_and_typeof/README.md) ([TypeScript Handbook — Typeof type operator ↗](https://www.typescriptlang.org/docs/handbook/2/typeof-types.html)).

## What to do

- Use `typeof` to test for a primitive type: `typeof x === "string"`, and likewise `"number"`, `"bigint"`, `"boolean"`, `"symbol"` and `"undefined"`.
- Test for `null` with `x === null`, never with `typeof`.
- Test for an array with `Array.isArray(x)`.
- To accept any object you can read properties from, write `x !== null && typeof x === "object"`, and also accept `typeof x === "function"` if functions count.
- Use `typeof name === "undefined"` only for a global that may not exist at all, such as `window`, and write it where the name is used: a helper function cannot do it for you.
- Do not expect `typeof` to protect a `let`, `const` or `class` read before its declaration.
- In TypeScript, rule out `null` before relying on a `typeof x === "object"` branch.

```javascript
// Kata solution: typeof's answer, except "null" for null and "array" for an
// array -- the two cases typeof cannot tell apart from other objects.
function kindOf(value) {
  if (value === null) return "null";
  if (Array.isArray(value)) return "array";
  return typeof value;
}

const values = [
  ["null", null],
  ["[1999, 250]", [1999, 250]],
  ["{ cents: 1999 }", { cents: 1999 }],
  ['"1999"', "1999"],
  ["1999", 1999],
  ["1999n", 1999n],
  ["undefined", undefined],
  ["() => 1999", () => 1999],
];

for (const [label, value] of values) {
  console.log(`${label.padEnd(17)}${kindOf(value)}`);
}
```

# `null` and `undefined` — two kinds of nothing

**Level:** 101 · for anyone who has checked a value against both null and undefined

**One line:** `undefined` is what the language fills in when nothing was assigned — a missing property, argument or return value — while `null` appears only where some code returns it; the two are `==` but not `===`, and `null + 1` is `1` while `undefined + 1` is `NaN`.

**Keywords:** `null`, `undefined`, `void`

JavaScript has two values that mean "nothing here", and each is the only value of its own type ([ECMA-262 ↗](https://tc39.es/ecma262/#sec-ecmascript-language-types-undefined-type)). The program below evaluates thirteen expressions that each come back with nothing, and prints which nothing it was; a template literal writes each one by its name.

## Reading the output

**The first nine answers are `undefined`, and nobody wrote it.** `total` was declared with `let total;` and never assigned. `order.discount` asks for a property the object does not have. `unitOf("rice")` returns its second parameter, which the call did not pass. `remember(1042)` does its work and ends without a `return` statement, and `stopEarly()` has a bare `return;`: a call that returns nothing returns `undefined`. `void 0` evaluates `0` and discards it, because the `void` operator always gives `undefined` ([ECMA-262 ↗](https://tc39.es/ecma262/#sec-void-operator)). `prices[5]` reads past the end of a two-element array, `find` found no price above 5000, and the `Map` has no `"beans"` entry.

**The last four answers are `null`, and each was chosen by the function that returned it.** `match` found no digit in `"rice"`. `Object.getPrototypeOf(Object.prototype)` is `null` because nothing sits above `Object.prototype`: it is where a property lookup stops ([The prototype chain](../../07_Prototypes_and_Classes/the_prototype_chain/README.md)). The `get` of `URLSearchParams` found no `sort` parameter. `JSON.parse` returned the `null` its text contained: JSON has a `null` literal and nothing for `undefined` ([RFC 8259 ↗](https://www.rfc-editor.org/rfc/rfc8259#section-3)).

Put `stock.get("beans")` beside `query.get("sort")`. Both ask for a key that is not there; `Map` answers `undefined` and `URLSearchParams` answers `null`. Which absence you get depends on who wrote the function, not on what went missing, so code that takes a value from somewhere else has to be ready for both.

`Number(null)` is `0` and `Number(undefined)` is `NaN`: those are the two answers the conversion ToNumber gives them ([ECMA-262 ↗](https://tc39.es/ecma262/#sec-tonumber)). The next four rows convert their operand the same way before they compute, so `null` behaves as `0` — `x + 1` is `1`, and `1999 - x` is still `1999` — while `undefined` becomes `NaN`, and every row that starts from `NaN` ends at `NaN`.

That makes `null` the quieter of the two bugs. A discount that arrives as `null` is subtracted as `0` and the total looks right; one that arrives as `undefined` turns the total into `NaN`, which at least shows.

`>=` converts too, so `null >= 0` is `true`. Yet `null > 0` is `false`, and so is `null == 0`: `==` does not turn `null` into a number at all. Its only loose match is `undefined`, as the next section shows, and [`<` and `>`](../../03_Equality_and_Coercion/comparing_with_less_than/README.md) takes the `>=` row apart.

The last row is not arithmetic. With a string on one side, `+` joins instead of adding ([The `+` operator](../../03_Equality_and_Coercion/the_plus_operator/README.md)), and each absence is written out by its name.

## `== null`, `??` and `?.` treat them alike; a default, JSON and `typeof` tell them apart

Ten checks, each applied to both values; the verdict compares what was printed for each. The six lines after the table try `== null` on the falsy values too.

<summary>The program</summary>

<!-- source:null_and_undefined_treated_alike_js -->
*[`null_and_undefined_treated_alike_js.js`](examples/null_and_undefined_treated_alike_js.js) in full — pasted here by `tools/run_examples.py` from the file CI runs.*

```javascript
// Each check applied to null and to undefined. A string result is printed in
// single quotes, so that the string 'null' cannot pass for the value null, and
// a check that throws prints the error's name.
const show = (value) => (typeof value === "string" ? `'${value}'` : String(value));
const attempt = (check, x) => {
  try {
    return show(check(x));
  } catch (error) {
    return `throws ${error.name}`;
  }
};

function withDefault(x = "fallback") {
  return x;
}

const checks = [
  ["x == null", (x) => x == null],
  ["x === null", (x) => x === null],
  ['x ?? "fallback"', (x) => x ?? "fallback"],
  ["x?.length", (x) => x?.length],
  ["x.length", (x) => x.length],
  ["withDefault(x)", (x) => withDefault(x)],
  ["JSON.stringify({ x })", (x) => JSON.stringify({ x })],
  ["JSON.stringify([x])", (x) => JSON.stringify([x])],
  ["typeof x", (x) => typeof x],
  ["String(x)", (x) => String(x)],
];

console.log("check".padEnd(24) + "x = null".padEnd(18) + "x = undefined".padEnd(18) + "verdict");
for (const [label, check] of checks) {
  const forNull = attempt(check, null);
  const forUndefined = attempt(check, undefined);
  const verdict = forNull === forUndefined ? "alike" : "differ";
  console.log(label.padEnd(24) + forNull.padEnd(18) + forUndefined.padEnd(18) + verdict);
}

// Loose equality with null picks out exactly these two values: not 0, not "",
// not false, not NaN.
console.log("");
for (const value of [null, undefined, 0, "", false, NaN]) {
  console.log(`${show(value).padEnd(10)}== null  ${value == null}`);
}
```

**Alike.** `x == null` is `true` for both, because loose equality counts `null` and `undefined` as equal to each other ([ECMA-262 ↗](https://tc39.es/ecma262/#sec-islooselyequal)). The six lines under the table show that it lets the other falsy values through: `0`, `''`, `false` and `NaN` are all falsy, and none of them is `== null`. So `x == null` is an exact test for "no value", not a loose one ([`===` and `==`](../../03_Equality_and_Coercion/strict_and_loose_equality/README.md) sets it beside the rest of `==`). `??` falls back for both, and `?.` stops at both and gives `undefined` either way, where reading `x.length` without the `?` throws a `TypeError` for both ([`?.` and `??`](../../06_Objects/optional_chaining_and_nullish_coalescing/README.md)).

**Different.** `===` converts nothing, so `undefined === null` is `false`. A default parameter fires only for `undefined`: `withDefault(null)` returns the `null` it was given ([Parameters](../../05_Functions/parameters_defaults_and_rest/README.md)), and the kata below shows a destructuring default doing the same ([Destructuring](../../04_Variables_and_Scope/destructuring/README.md)). `typeof null` is `'object'`, the answer [`typeof`](../the_typeof_operator/README.md) explains, and `String` writes each one by its name.

**JSON keeps one and loses the other.** `JSON.stringify({ x })` writes `{"x":null}` for `null` but leaves an `undefined` property out entirely: `'{}'`. In an array both come out as `null` — `'[null]'` — so the text no longer says which one it was ([JSON](../../06_Objects/json/README.md)).

## `undefined` is a name a function can reuse; `null` is a literal

Four small files. The first declares its own `undefined`; the next two assign to the global one, as sloppy code (`.cjs`) and as a module (`.mjs`, which is always strict); the last assigns to `null`. The driver prints what each run printed, the error line of its stderr, and its exit status.

<details markdown="1">
<summary>The program</summary>

<!-- source:null_and_undefined_names_sh -->
*[`null_and_undefined_names_sh.sh`](examples/null_and_undefined_names_sh.sh) in full — pasted here by `tools/run_examples.py` from the file CI runs.*

```bash
# `undefined` is a name, which a function can declare for itself; `null` is a
# literal, like `42`. Four small files, each run by node: what it printed, the
# error line of its stderr (never the stack trace), and its exit status. A .cjs
# file is sloppy-mode code; an .mjs file is a module, which is always strict.
dir=$(mktemp -d)
trap 'rm -rf "$dir"' EXIT
cd "$dir" || exit 1

cat > shadow_undefined.mjs <<'EOF'
function describe() {
  let undefined = 1;
  return `typeof undefined is ${typeof undefined}, typeof void 0 is ${typeof void 0}`;
}
console.log(`inside describe():  ${describe()}`);
console.log(`outside:            typeof undefined is ${typeof undefined}`);
EOF

cat > assign_undefined.cjs <<'EOF'
console.log("this line runs");
undefined = 1;
console.log(`after the assignment, typeof undefined is ${typeof undefined}`);
EOF
cp assign_undefined.cjs assign_undefined.mjs

cat > assign_null.mjs <<'EOF'
console.log("this line never runs");
null = 1;
EOF

for file in shadow_undefined.mjs assign_undefined.cjs assign_undefined.mjs assign_null.mjs; do
  echo "\$ node $file"
  node "$file" 2>stderr.txt
  status=$?
  grep -E '^[A-Za-z]*Error' stderr.txt
  echo "exit status: $status"
  [ "$file" = assign_null.mjs ] || echo
done
```

**`shadow_undefined.mjs`.** Inside `describe()`, the name `undefined` belongs to a local variable that holds the number 1, so `typeof undefined` is `number` there. `typeof void 0` is still `undefined`: `void` is an operator, not a name, so no declaration can change what it gives. Outside the function, the global `undefined` is untouched.

**`assign_undefined.cjs` and `assign_undefined.mjs`.** The same three lines, twice. The global `undefined` is a property of the global object that cannot be written: ECMA-262 gives it `[[Writable]]: false` ([ECMA-262 ↗](https://tc39.es/ecma262/#sec-undefined)). Sloppy code ignores the failed write, and the next line finds `undefined` unchanged. Strict code throws a `TypeError` instead, and the module stops with exit status 1 ([Strict mode](../../01_Running_JavaScript/strict_mode/README.md)).

**`assign_null.mjs`.** Its first line never printed. Node rejected the file while parsing it, before running anything: `null` is a literal, like `42` or `true`, and `null = 1` makes no more sense than `42 = 1`. ECMA-262 lists `null` among the reserved words, which cannot name a variable either; `undefined` is not on that list ([ECMA-262 ↗](https://tc39.es/ecma262/#sec-keywords-and-reserved-words)).

## TypeScript keeps them apart as two types

Under `strictNullChecks`, `null` and `undefined` are types of their own, and `tsc` will not let a value that may be either one reach a property access unchecked. The check comes with `strict`, which the repo's `tsconfig.json` sets and which TypeScript 7 turns on even when a config does not ([`strict`](../../22_TypeScript_Basics/strict_mode_in_typescript/README.md)).

## What to do

- Test for "no value" with `x == null`, or supply a fallback with `x ?? fallback`. Both catch `null` and `undefined`, and let `0`, `""` and `false` through.
- Tell the two apart with `=== null` or `=== undefined` only where they mean different things to your code — a JSON field sent as `null` on purpose, say, against one that was left out.
- Do not count on a default parameter or a destructuring default to replace `null`. If `null` can arrive, write `x ?? fallback` inside the function.
- Check amounts before arithmetic: `null` passes silently as `0`, and `undefined` turns the result into `NaN`.
- Never declare a variable called `undefined`. Where you need the value itself and cannot trust the name, `void 0` is the spelling no declaration can change.
- In TypeScript, keep `strict` on, so that `tsc` reports every place a `null` or an `undefined` can reach a property access.

```javascript
// Kata solution: one check that treats a left-out volume, undefined and null
// alike, and keeps a stored 0.
function volumeOf(settings) {
  return settings.volume ?? 50;
}

// Tempting, and wrong for a stored 0: || falls back on 0 as well.
function withOr(settings) {
  return settings.volume || 50;
}

// Tempting, and wrong for JSON's null: the default fires only for undefined.
function withDefault(settings) {
  const { volume = 50 } = settings;
  return volume;
}

const inputs = [
  ["{}", {}],
  ["{ volume: undefined }", { volume: undefined }],
  [`JSON.parse('{"volume":null}')`, JSON.parse('{"volume":null}')],
  ["{ volume: 0 }", { volume: 0 }],
  ["{ volume: 80 }", { volume: 80 }],
];

console.log("settings".padEnd(32) + "volumeOf".padEnd(10) + "|| 50".padEnd(8) + "{ volume = 50 }");
for (const [label, settings] of inputs) {
  console.log(
    label.padEnd(32) +
      String(volumeOf(settings)).padEnd(10) +
      String(withOr(settings)).padEnd(8) +
      String(withDefault(settings)),
  );
}
```

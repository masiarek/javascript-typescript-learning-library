# Eight types — seven primitives and the object

**Level:** 101 · for anyone who has written a line of JavaScript

**One line:** Every value has one of eight types — seven primitives (undefined, null, boolean, number, bigint, string, symbol) and Object — and `Object(v) === v` is `true` only for an object; a primitive takes no property and never changes, while arrays, functions, dates, regular expressions and the instances of your own classes are kinds of Object, not types of their own.

**Keywords:** `primitive`, `data types`, `immutable`

The specification names eight types, and every value belongs to exactly one of them. The program below takes the twelve values this page asks about — `undefined`, `null`, `true`, `1`, `1n`, `"s"`, `Symbol()`, `{}`, `[]`, a function, a `Date` and a regular expression — and sorts them with a single test, `Object(v) === v`, without using `typeof`.

```javascript
// Twelve values, sorted the way the language sorts them. Object(v) hands back
// v itself only when v is already an object; for a primitive it has to make a
// new object, so Object(v) === v is the test. No typeof anywhere.
function classify(value) {
  const made = Object(value);
  if (made === value) {
    return { same: true, made: "the same object", is: "object", type: "Object" };
  }
  if (Object.getPrototypeOf(made) === Object.prototype) {
    // Only undefined and null get a new, empty, ordinary object.
    return { same: false, made: "a new empty object", is: "primitive", type: value === null ? "Null" : "Undefined" };
  }
  // Every other primitive gets a wrapper, named after its type.
  const wrapper = made.constructor.name;
  return { same: false, made: `a ${wrapper} wrapper`, is: "primitive", type: wrapper };
}

const samples = [
  ["undefined", undefined],
  ["null", null],
  ["true", true],
  ["1", 1],
  ["1n", 1n],
  ['"s"', "s"],
  ["Symbol()", Symbol()],
  ["{}", {}],
  ["[]", []],
  ["() => {}", () => {}],
  ["new Date(0)", new Date(0)],
  ["/s/", /s/],
];

console.log(`${"value".padEnd(13)}${"Object(v) === v".padEnd(17)}${"Object(v) returns".padEnd(21)}${"so it is".padEnd(11)}type`);
const types = [];
let primitives = 0;
for (const [label, value] of samples) {
  const row = classify(value);
  // For an object, name the constructor that made it: a kind of object, not a type.
  const type = row.same ? `Object, made by ${value.constructor.name}` : row.type;
  console.log(`${label.padEnd(13)}${String(row.same).padEnd(17)}${row.made.padEnd(21)}${row.is.padEnd(11)}${type}`);
  if (!types.includes(row.type)) types.push(row.type);
  if (!row.same) primitives += 1;
}
console.log(`${samples.length} values: ${primitives} primitives, ${samples.length - primitives} objects`);
console.log(`${types.length} types: ${types.join(", ")}`);
```

## Reading the output

- **The test.** `Object(v)` turns `v` into an object. When `v` is already an object there is nothing to do, and it returns `v` itself, so the comparison is `true`: the last five rows. For a primitive it must return some other value, an object, so the comparison is `false`: the first seven rows. Those are the steps ECMA-262 gives for [`Object ( value )` ↗](https://tc39.es/ecma262/#sec-object-value).
- **`undefined` and `null`** get a new, empty, ordinary object: they are the two primitives with no wrapper ([MDN — Primitive values ↗](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Data_structures#primitive_values)). The program names their types by comparing with `undefined` and `null` directly.
- **The other five primitives** each get a wrapper object, and the wrapper's constructor carries the name of the type: `Boolean`, `Number`, `BigInt`, `String`, `Symbol`. A property read on a primitive, such as `"s".length`, is looked up on a wrapper like these ([MDN — Primitive ↗](https://developer.mozilla.org/en-US/docs/Glossary/Primitive)); [Primitives and wrappers](../primitives_and_wrapper_objects/README.md) is the page about that.
- **`{}`, `[]`, the arrow function, the `Date` and the regular expression** are all of one type, Object. What differs is the constructor that made each of them — `Object`, `Array`, `Function`, `Date`, `RegExp` — so an array or a function is a kind of object, not a type.
- **The last two lines** count the rows: seven primitives and five objects, spread over eight types. That is the whole of ECMA-262's list: Undefined, Null, Boolean, String, Symbol, Number, BigInt and Object ([ECMA-262 — ECMAScript language types ↗](https://tc39.es/ecma262/#sec-ecmascript-language-types)), where a primitive value is a member of any of the first seven ([ECMA-262 — primitive value ↗](https://tc39.es/ecma262/#sec-primitive-value)).

## What can an object do that a string cannot?

Three things: hold a property of its own, change in place, and be told apart from another object with the same contents. The program tries each on an object, `order`, and on a string, `code`. The file is an ES module, and module code always runs in [strict mode](../../01_Running_JavaScript/strict_mode/README.md), where an assignment that cannot happen throws a `TypeError` ([MDN — Strict mode for modules ↗](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Strict_mode#strict_mode_for_modules)); the program catches each error and prints its message.

```javascript
// Three things an object can do, tried on an object and then on a string.
// This file is an ES module, so it runs in strict mode: an assignment that
// cannot happen throws a TypeError instead of being ignored.
function attempt(label, action) {
  let result;
  try {
    result = action();
  } catch (error) {
    result = `${error.name}: ${error.message}`;
  }
  console.log(`   ${label.padEnd(28)}${result}`);
}

const order = { code: "ab-100" }; // an object
let code = "ab-100"; // a string, one of the seven primitives

console.log("1. hold a property of its own");
attempt('order.note = "fragile"', () => {
  order.note = "fragile";
  return `order.note is "${order.note}"`;
});
attempt('code.note = "fragile"', () => {
  code.note = "fragile";
  return `code.note is "${code.note}"`;
});

console.log("2. change in place");
attempt('order.code = "AB-100"', () => {
  order.code = "AB-100";
  return `order is ${JSON.stringify(order)}`;
});
attempt('code[0] = "A"', () => {
  code[0] = "A";
  return `code is "${code}"`;
});
attempt("code.toUpperCase()", () => `returns "${code.toUpperCase()}"; code is still "${code}"`);
attempt("code = code.toUpperCase()", () => {
  code = code.toUpperCase();
  return `code is "${code}": a new string in the same variable`;
});

console.log("3. be compared by identity");
const first = { code: "ab-100" };
const second = { code: "ab-100" };
attempt("first === second", () => `${first === second}: two objects, built alike`);
attempt("first === first", () => `${first === first}: one object`);
attempt('"ab-100" === "ab-" + "100"', () => `${"ab-100" === "ab-" + "100"}: two strings, same characters`);
```

- **1. A property of its own.** The object takes `note`. The string refuses it with `TypeError: Cannot create property 'note' on string 'ab-100'`: a primitive has nowhere to keep a property. In sloppy code the same assignment is ignored without a word instead, and the string still has no `note` ([MDN — Strict mode: setting properties on primitive values ↗](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Strict_mode#setting_properties_on_primitive_values)).
- **2. Change in place.** The object changes, and keeps the `note` from step 1. `code[0] = "A"` throws, because a string's characters are read-only properties ([ECMA-262 — String exotic objects ↗](https://tc39.es/ecma262/#sec-string-exotic-objects)). `toUpperCase()` leaves `code` alone as well: it returns a new string. What can change is the variable — `code = code.toUpperCase()` puts a new string into it, which is why `code` is declared with `let`. MDN's glossary draws the same line between a primitive and a variable that holds one ([MDN — Primitive ↗](https://developer.mozilla.org/en-US/docs/Glossary/Primitive)).
- **3. Identity.** Each object literal makes a new object, so `first === second` is `false` although the two look the same; an object is `===` only to itself. Two strings have no identity to tell apart: `===` compares their characters ([ECMA-262 — SameValueNonNumber ↗](https://tc39.es/ecma262/#sec-samevaluenonnumber)), so `"ab-100"` equals `"ab-" + "100"`. [Values and references](../values_and_references/README.md) follows the difference into assignment and function calls.

## Why are there two numeric types?

Until ES2020 there was one: the list of types in ES2019 has Number as its only numeric type, and BigInt joins the list in ES2020 ([ES2019 — ECMAScript language types ↗](https://262.ecma-international.org/10.0/#sec-ecmascript-language-types), [ES2020 — ECMAScript language types ↗](https://262.ecma-international.org/11.0/#sec-ecmascript-language-types)). The program shows what a number cannot do and a bigint can.

```javascript
  ["typeof 1", JSON.stringify(typeof 1)],
  ["typeof 1.5", JSON.stringify(typeof 1.5)],
  ["typeof 1n", JSON.stringify(typeof 1n)],
  ["1 === 1.0", String(1 === 1.0)],
  ["1 === 1n", String(1 === 1n)],
  ["Number.MAX_SAFE_INTEGER", String(Number.MAX_SAFE_INTEGER)],
  ["2 ** 53 + 1", String(2 ** 53 + 1)],
  ["2 ** 53 + 1 === 2 ** 53", String(2 ** 53 + 1 === 2 ** 53)],
  ["2n ** 53n + 1n", `${2n ** 53n + 1n}n`],
  ["2n ** 53n + 1n === 2n ** 53n", String(2n ** 53n + 1n === 2n ** 53n)],
  ["7 / 2", String(7 / 2)],
  ["7n / 2n", `${7n / 2n}n`],
];
for (const [expression, result] of rows) {

}
```

- **`typeof` answers `"number"` for `1` and for `1.5`.** Whole or fractional, a number is one type, and `1 === 1.0` is `true` because `1.0` is the same value as `1` ([Every number is a double](../../10_Numbers_and_Math/every_number_is_a_double/README.md)). `typeof 1n` is `"bigint"`, and `1 === 1n` is `false`: `===` is `false` whenever the two types differ ([ECMA-262 — IsStrictlyEqual ↗](https://tc39.es/ecma262/#sec-isstrictlyequal)).
- **A number runs out of whole numbers.** A number is a 64-bit IEEE 754 double ([ECMA-262 — The Number Type ↗](https://tc39.es/ecma262/#sec-ecmascript-language-types-number-type)). `Number.MAX_SAFE_INTEGER` is 9007199254740991, 2^53 − 1, and just past 2^53 the doubles skip a whole number: `2 ** 53 + 1` prints `9007199254740992` and is `===` to `2 ** 53` ([MDN — Number.MAX_SAFE_INTEGER ↗](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Number/MAX_SAFE_INTEGER)). [Safe integers](../../10_Numbers_and_Math/safe_integers/README.md) maps where the gaps are.
- **A bigint stays exact past 2^53, and holds only whole numbers.** `2n ** 53n + 1n` prints `9007199254740993n` and differs from `2n ** 53n`; `7 / 2` is `3.5`, but `7n / 2n` is `3n`. What happens when the two types meet in one expression is the subject of [BigInt](../bigint/README.md).

## Why can you not add a ninth type?

The list is part of the language, and only a new edition of the standard changes it: ES5.1 had six types, ES2015 added Symbol, and ES2020 added BigInt ([ES5.1 ↗](https://262.ecma-international.org/5.1/#sec-8), [ES2015 ↗](https://262.ecma-international.org/6.0/#sec-ecmascript-language-types), [ES2020 ↗](https://262.ecma-international.org/11.0/#sec-ecmascript-language-types)). Nothing a program writes adds to it. What a program writes instead is a class, so the program asks what a class makes, then runs the first program's test over a dozen other things a program can build.

## What to do

- To ask whether a value is a primitive, compare `Object(value) !== value`; to ask for one particular type, use [`typeof`](../the_typeof_operator/README.md) or `value === null`.
- Treat a primitive as finished: to change a string, build a new one and assign it to the variable.
- Keep information about a primitive in an object beside it, never on the primitive itself.
- Use `===` on two objects only when you mean "the same object"; to compare contents, compare their fields.
- Use `bigint` for whole numbers that can pass 2^53, and `number` for everything else.
- Write a class when you need a new kind of object, and expect it to be of type Object like every other.

```javascript
// Object(value) returns value itself only when value is already an object.
const isPrimitive = (value) => Object(value) !== value;

const values = [
  ["1999", 1999],
  ['"1999"', "1999"],
  ["1999n", 1999n],
  ["true", true],
  ["null", null],
  ["undefined", undefined],

  ["new Date(0)", new Date(0)],

const primitives = values.filter(([, value]) => isPrimitive(value)).map(([label]) => label);
const objects = values.filter(([, value]) => !isPrimitive(value)).map(([label]) => label);
console.log(`primitives (${primitives.length}): ${primitives.join(", ")}`);
```

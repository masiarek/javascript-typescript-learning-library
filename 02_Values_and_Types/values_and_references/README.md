# Values and references — what assignment copies

**Level:** 101 · for anyone who has changed one variable and seen another change

**One line:** Assignment copies what a variable holds, and for an object that is a reference: after `const b = a`, `b.count = 2` changes `a.count` too; a function can change an object you pass it, but assigning to its parameter never changes which object your variable holds; and `{ n: 1 } === { n: 1 }` is `false`, because `===` on two objects asks whether they are one object.

**Keywords:** `pass by sharing`, `pass by reference`, `object reference`, `object identity`

A variable holds a value, and assignment copies that value into another variable. A string is a [primitive ↗](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Data_structures#primitive_values), so the variable holds the string itself; an object is [a reference type ↗](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Working_with_objects#comparing_objects), so the variable holds a reference to it. The program does the same two things to an object and to a string: it changes the value through a second variable, and it assigns something new to a second variable.

## Reading the output

- **`b.count = 2` changed `a.count`.** The program never wrote through `a`, yet `a.count` is 2. `const b = a` copied the reference that `a` held, so `a` and `b` name one object, and `a === b` is `true`. `b` is `const` and the write went through anyway: `const` stops the variable from being assigned again, not the object from changing ([MDN — `const` ↗](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Statements/const#description)).
- **`c = { count: 9 }` did not change `a`.** Assigning to `c` put a reference to a new object into `c`. The object `a` holds is untouched (`a.count` is still 2), and `a === c` is now `false`. Assignment never ties two variables together: they can hold the same reference, and assigning to one replaces only what that one holds.
- **`t[0] = "M"` threw.** It is the same kind of write as `b.count = 2`, aimed at a string, and a string cannot be changed once it exists ([MDN — the String type ↗](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Data_structures#string_type)). Every `.js` example here is an ES module, and module code is always [strict mode code ↗](https://tc39.es/ecma262/#sec-strict-mode-code), where the failed write throws a `TypeError`; outside strict mode the same write [fails silently ↗](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Strict_mode#failing_to_assign_to_object_properties). `s` is still `"milk"`.
- **`u += "!"` did not change `s`.** It built a new string, `"milk!"`, and assigned that to `u`. Since nothing can change a string, it makes no difference whether `let u = s` copied the characters or shared them: no operation through `u` can reach `s`.

So a variable that holds an object allows two different things. You can change the object (`b.count = 2`), and every variable holding that reference sees it. Or you can assign the variable (`c = { count: 9 }`), and no other variable sees it. A variable that holds a string allows only the second.

## A function can change your object, but not your variable

A parameter is a variable of the function's own, and the call copies the argument into it, as `const b = a` did. The program calls three functions: `markPaid` writes to a property of its parameter, `cancel` assigns a new object to its parameter, and `swap` exchanges its two parameters.

<summary>The program</summary>

<!-- source:values_and_references_arguments_js -->
*[`values_and_references_arguments_js.js`](examples/values_and_references_arguments_js.js) in full — pasted here by `tools/run_examples.py` from the file CI runs.*

```javascript
// A parameter is a variable of the function's own, and the call copies the
// argument into it, as `const b = a` does. So the function can write to the
// caller's object, but assigning to the parameter moves only its own variable.
const show = (label, value) => console.log(`  ${label.padEnd(14)}${value}`);

function markPaid(order) {
  order.status = "paid"; // a write to the object the caller also holds
}

function cancel(order) {
  order = { status: "cancelled" }; // points this function's variable elsewhere
  return order.status;
}

function swap(first, second) {
  const held = first;
  first = second;
  second = held;
  return `${first.id} ${second.id}`;
}

// let, not const: nothing below is held back by const.
let order = { status: "open" };
console.log("markPaid(order);");
markPaid(order);
show("order.status", order.status);

console.log("cancel(order);");
show("returned", cancel(order));
show("order.status", order.status);

let left = { id: 1 };
let right = { id: 2 };
console.log("swap(left, right);");
show("returned", swap(left, right));
show("left.id", left.id);
show("right.id", right.id);
```

- `markPaid(order)` wrote `order.status = "paid"` through its parameter, and the caller's `order.status` is `paid`: the parameter held the caller's reference, so the write landed on the caller's object.
- `cancel(order)` assigned a new object to its parameter. Its own variable then held the status `cancelled` (the `returned` line), but the caller's `order.status` is still `paid`.
- `swap(left, right)` exchanged its own two variables (`returned` is `2 1`), and the caller's `left.id` and `right.id` are still 1 and 2, although both are `let`.

MDN's functions guide describes the same split: the caller does not see a new value assigned to a parameter, but does see a change to the properties of an object passed in ([MDN — function declarations ↗](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Functions#function_declarations)). The usual name for it is *pass by sharing*: the function shares the caller's object, not the caller's variable. It is not *pass by reference*, under which a parameter stands for the caller's variable itself, and a working `swap` is the usual test for that ([Wikipedia — Evaluation strategy ↗](https://en.wikipedia.org/wiki/Evaluation_strategy#Call_by_reference)). The names are used loosely: the same article notes that Java programmers call this pass by value, the value being the reference. To change which object a caller's variable holds, return the new object and let the caller assign it.

## `===` on two objects asks whether they are one object

Two object literals make two objects, however alike their contents. The program compares objects, and one pair of strings, in several ways.

<!-- source:values_and_references_identity_js -->
*[`values_and_references_identity_js.js`](examples/values_and_references_identity_js.js) in full — pasted here by `tools/run_examples.py` from the file CI runs.*

```javascript
// `===` on two objects asks one question: are they the same object? It never
// looks inside, so two objects with the same contents are not ===.
import { isDeepStrictEqual } from "node:util";

const row = (code, value) => console.log(`${code.padEnd(34)}${value}`);

console.log("const a = { n: 1 }; const b = a;");
const a = { n: 1 };
const b = a;
row("{ n: 1 } === { n: 1 }", { n: 1 } === { n: 1 });
row("a === b", a === b);
row("[1, 2] === [1, 2]", [1, 2] === [1, 2]);
row("{ n: 1 } == { n: 1 }", { n: 1 } == { n: 1 });
row('"milk" === "mi" + "lk"', "milk" === "mi" + "lk");
row("[a].includes({ n: 1 })", [a].includes({ n: 1 }));
row("new Set([a, b, { n: 1 }]).size", new Set([a, b, { n: 1 }]).size);
row("isDeepStrictEqual(a, { n: 1 })", isDeepStrictEqual(a, { n: 1 }));
```
<!-- /source -->

{ n: 1 } === { n: 1 }             false

<!-- /output -->

- `{ n: 1 } === { n: 1 }` is `false`: two literals, two objects. `a === b` is `true` because `const b = a` copied the reference. `[1, 2] === [1, 2]` is `false` for the same reason, since an array is an object.
- `{ n: 1 } == { n: 1 }` is `false` too: when both operands are objects, `==` does exactly what `===` does ([ECMA-262 — IsLooselyEqual ↗](https://tc39.es/ecma262/#sec-islooselyequal), step 1). What `==` does with operands of different types is the subject of [`===` and `==`](../../03_Equality_and_Coercion/strict_and_loose_equality/README.md).
- `"milk" === "mi" + "lk"` is `true`. Two strings are equal when they hold the same code units in the same positions ([ECMA-262 — SameValueNonNumber ↗](https://tc39.es/ecma262/#sec-samevaluenonnumber)), even when one of them was just built by `+`.
- `[a].includes({ n: 1 })` is `false`, and `new Set([a, b, { n: 1 }])` holds 2 values: `a` and `b` are one object, and the literal is another. `includes` and `Set` compare objects by identity, as `===` does.
- `isDeepStrictEqual(a, { n: 1 })` is `true`: it compares contents. It comes from Node's `node:util` module, not from the language ([Node docs — `util.isDeepStrictEqual` ↗](https://nodejs.org/docs/latest-v24.x/api/util.html#utilisdeepstrictequalval1-val2-options)).

## `{ ...a }` is a new object, but the array inside it is shared

Spread copies the properties of `a` into a new object, one level deep ([MDN — spread syntax ↗](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Operators/Spread_syntax)). Here one of those properties holds an array.

```javascript
// `{ ...a }` makes a new object and copies a's properties into it, one level
// deep: a property that holds an array copies the reference to that array.
const show = (label, value) => console.log(`  ${label.padEnd(22)}${value}`);

console.log('const a = { owner: "ana", items: ["milk"] };');
const a = { owner: "ana", items: ["milk"] };
console.log('const c = { ...a }; c.owner = "ben"; c.items.push("eggs");');
const c = { ...a };
c.owner = "ben";
c.items.push("eggs");
show("c === a", c === a);
show("c.items === a.items", c.items === a.items);
show("a.owner", JSON.stringify(a.owner));
show("a.items", JSON.stringify(a.items));
```

## What to do

- Read `const b = a`, when `a` holds an object, as "`b` is a second name for that object", never as a copy.
- To get an object of your own, copy it, and remember that `{ ...a }` copies one level only.
- In a function, do not write to an object you were passed unless changing it is the function's job; return a new object instead.
- To change which object a caller's variable holds, return the new object and let the caller assign it.
- Use `===` on objects only to ask "the same object?". To compare contents, compare the properties you care about, or call `util.isDeepStrictEqual` in Node.
- In TypeScript, treat `readonly` and `as const` as a promise about one variable: any other variable holding the same object can still write to it.

// Kata solution. withItem hands back a new cart and leaves the one it was
// given alone. `{ ...cart }` by itself would still share the items array,

  return { ...cart, items: [...cart.items, item] };

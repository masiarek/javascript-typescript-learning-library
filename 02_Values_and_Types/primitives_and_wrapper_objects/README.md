# Primitives and wrappers — why `"abc".length` works and `new String` is a trap

**Level:** 201 · for anyone who has called a method on a string and wondered where it came from

**One line:** `"abc".length` works because the lookup wraps the string in a temporary `String` object — a sloppy-mode method is even handed a new wrapper as `this` on every call — while `new String("abc")` keeps its wrapper, so `typeof` says `"object"`, two equal ones are not `===`, and `new Boolean(false)` is truthy.

**Keywords:** `new String`, `new Number`, `new Boolean`, `wrapper object`

A primitive — a string, a number, a boolean — is a value, not an object, yet `"abc".length` and `"abc".toUpperCase()` work ([MDN — Primitive ↗](https://developer.mozilla.org/en-US/docs/Glossary/Primitive)). `String`, `Number` and `Boolean` can also be called with `new`, which makes a wrapper object around the primitive and keeps it. The program below puts three falsy primitives beside their wrappers, and builds each value twice so that it can be compared with its twin.

## Reading the output

**`typeof`.** Each primitive answers with the name of its type, and each wrapper answers `object`: `new String("")` is an object that holds a string, not a string ([`typeof`](../the_typeof_operator/README.md) lists all eight answers).

**truthy.** `""`, `0` and `false` are falsy, and all three wrappers are truthy — `new Boolean(false)` included, so `new Boolean(false) ? 1 : 2` is `1`. Truthiness never looks inside an object: ToBoolean gives `true` for an object whatever it holds ([ECMA-262 ↗](https://tc39.es/ecma262/#sec-toboolean)), apart from one browser-only exception that [Truthy and falsy](../../03_Equality_and_Coercion/truthy_and_falsy/README.md) names.

**instanceof.** The fourth column tests each value against its own wrapper constructor: `String`, `Number` or `Boolean`. Only the wrappers pass. `instanceof` returns `false` for any value that is not an object ([ECMA-262 ↗](https://tc39.es/ecma262/#sec-ordinaryhasinstance)), so `"abc" instanceof String` is `false`, although the next section shows `"abc"` taking its methods from `String.prototype` ([`instanceof`](../../07_Prototypes_and_Classes/instanceof/README.md)).

**=== twin.** Two equal primitives are `===`. Two wrappers are two objects, and two objects are `===` only when they are the same object ([ECMA-262 ↗](https://tc39.es/ecma262/#sec-isstrictlyequal)), so `new String("a") === new String("a")` is `false`, as is every wrapper's comparison with its twin in the table. Against a primitive, `==` first turns the wrapper back into its primitive ([ECMA-262 ↗](https://tc39.es/ecma262/#sec-islooselyequal)), so `new String("abc") == "abc"` is `true` while `===` says `false` ([ToPrimitive](../../03_Equality_and_Coercion/toprimitive/README.md)).

**Without `new`.** `typeof String(42)` is `string`: called without `new`, `String` converts its argument and returns a primitive, where `new String("abc")` returns a wrapper. The same function does two jobs, and `new` decides which.

## Where `"abc".length` comes from: a wrapper made for the lookup

A primitive has no properties of its own. To read one, the specification converts the primitive into its wrapper object with ToObject and reads the property from that, adding that an engine may skip actually creating the object, since no code can reach it ([ECMA-262 ↗](https://tc39.es/ecma262/#sec-getvalue)). What a program can see is where the property comes from, and what `this` a method is handed. This program is a `.cjs` file, which is sloppy-mode code except inside a function that says `"use strict"`.

<summary>The program</summary>

<!-- source:primitives_and_wrappers_this_cjs -->
*[`primitives_and_wrappers_this_cjs.cjs`](examples/primitives_and_wrappers_this_cjs.cjs) in full — pasted here by `tools/run_examples.py` from the file CI runs.*

```javascript
// A .cjs file is sloppy-mode code unless a function says "use strict".
const sku = "SKU-1042";

// The primitive has no methods of its own; the lookup finds String.prototype's.
console.log(`sku.toUpperCase === String.prototype.toUpperCase  ${sku.toUpperCase === String.prototype.toUpperCase}`);

// Two methods added to String.prototype, one sloppy and one strict, each
// returning the `this` it was called with.
String.prototype.sloppySelf = function () {
  return this;
};
String.prototype.strictSelf = function () {
  "use strict";
  return this;
};

const first = sku.sloppySelf();
const second = sku.sloppySelf();
console.log("sloppy method, called twice:");
console.log(`  typeof this                 ${typeof first}`);
console.log(`  this instanceof String      ${first instanceof String}`);
console.log(`  this.valueOf() === sku      ${first.valueOf() === sku}`);
console.log(`  first this === second this  ${first === second}`);

const strictThis = sku.strictSelf();
console.log("strict method:");
console.log(`  typeof this                 ${typeof strictThis}`);
console.log(`  this === sku                ${strictThis === sku}`);

// Leave String.prototype as it was found.
delete String.prototype.sloppySelf;
delete String.prototype.strictSelf;
```

**The first line.** `sku.toUpperCase` is the very function stored on `String.prototype`: a string borrows its methods from its wrapper type's prototype ([String methods](../../09_Strings_and_Unicode/string_methods/README.md)).

**The sloppy method.** `sloppySelf` returns its `this`, and it is an object: a `String` wrapper whose `valueOf()` is `sku`. Two calls return two different wrappers. A sloppy function turns a primitive `this` into an object with ToObject on every call ([ECMA-262 ↗](https://tc39.es/ecma262/#sec-ordinarycallbindthis)), so a sloppy method never sees the string itself, and never the same wrapper twice.

**The strict method.** `strictSelf` is handed the primitive as it is: `typeof this` is `string`, and `this === sku`. Module code and every class body are strict ([ECMA-262 ↗](https://tc39.es/ecma262/#sec-strict-mode-code)), so a method written in either gets the primitive, as `strictSelf` does ([`this`](../../05_Functions/this_is_set_by_the_call/README.md)).

The program adds its two methods to `String.prototype` only to watch `this`, and deletes them at the end, since every string in the program looks its methods up on that one object.

## Setting a property on a primitive: lost in sloppy code, a `TypeError` in strict code

The same three lines, run as a sloppy `.cjs` file and as a strict `.mjs` module:

```bash

console.log(`sku.note is ${sku.note}`);
EOF
cp note_sloppy.cjs note_strict.mjs

for file in note_sloppy.cjs note_strict.mjs; do
  echo "\$ node $file"
  node "$file" 2>stderr.txt
  status=$?
  grep -E '^[A-Za-z]*Error' stderr.txt
  echo "exit status: $status"
  [ "$file" = note_strict.mjs ] || echo
done
```

A primitive cannot hold a property, so the assignment fails in both runs; the two modes differ only in what they do about the failure. In the specification's terms, the property write returns `false` because its receiver, the string, is not an object ([ECMA-262 ↗](https://tc39.es/ecma262/#sec-ordinarysetwithowndescriptor)), and the assignment turns that `false` into a `TypeError` only in strict code ([ECMA-262 ↗](https://tc39.es/ecma262/#sec-putvalue)). So the sloppy run carries on, reads `sku.note` back as `undefined`, and exits 0. The strict run stops at the assignment with the `TypeError` and exit status 1, and its `console.log` never runs ([Strict mode](../../01_Running_JavaScript/strict_mode/README.md)).

## `Symbol` and `BigInt` refuse `new`; `Object()` wraps them anyway

`new Symbol("id")` and `new BigInt(10)` throw a `TypeError`, where `new String("id")` makes an object. Each of the two functions starts by checking whether it was called with `new`, and throws if it was ([ECMA-262: Symbol ↗](https://tc39.es/ecma262/#sec-symbol-description), [ECMA-262: BigInt ↗](https://tc39.es/ecma262/#sec-bigint-constructor-number-value)). MDN gives the reason for symbols: to stop anyone making a wrapper object by accident where they meant a new symbol value ([MDN — Symbol() ↗](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Symbol/Symbol)). Called without `new`, each returns a primitive of its own type, `symbol` and `bigint`.

`Object(value)` turns a primitive into its wrapper, with the same ToObject that the property lookup uses ([ECMA-262 ↗](https://tc39.es/ecma262/#sec-object-value)). All three results are objects, each is an instance of its own constructor, and `valueOf()` hands back the primitive inside. So wrappers for symbols and BigInts exist; `new` is only refused as the way to make one. The two primitives with no wrapper type at all are `null` and `undefined` ([MDN — JavaScript data types ↗](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Data_structures#primitive_values)).

## TypeScript keeps `string` and `String` apart

`tsc` has a type for each: `string` for the primitive, and `String` for the wrapper object. A function that asks for a `string` refuses a wrapper:

## What to do

- Never write `new String`, `new Number` or `new Boolean`. To convert, call the function without `new`: `String(x)`, `Number(x)` and `Boolean(x)` return primitives.
- If a wrapper can reach you from code you do not control, turn it back into its primitive with `valueOf()` before you compare it or test it for truthiness.
- Test for a string with `typeof value === "string"`, and add `|| value instanceof String` only where wrappers can arrive.
- Do not store data on a primitive: `sku.note = ...` is lost or throws. Keep the data in an object, or in a `Map` keyed by the primitive.
- Leave `String.prototype` alone in real code. If you do write a method that is called on primitives, write it in a module or a class, where `this` is the primitive and not a new wrapper per call.
- In TypeScript, write `string`, `number`, `boolean`, `symbol` and `bigint` in types — never `String`, `Number`, `Boolean`, `Symbol` or `BigInt`.

// Kata solution: unwrap a String, Number or Boolean wrapper to the primitive
// inside it, and hand back every other value unchanged.
function unwrap(value) {
  if (value instanceof String || value instanceof Number || value instanceof Boolean) {
    return value.valueOf();
  }
  return value;
}

const rows = [
  ['""', () => ""],
  ['new String("")', () => new String("")],
  ["0", () => 0],
  ["new Number(0)", () => new Number(0)],
  ["false", () => false],
  ["new Boolean(false)", () => new Boolean(false)],
  ["{ count: 0 }", () => ({ count: 0 })],
];

console.log("unwrap(value)".padEnd(20) + "typeof".padEnd(10) + "truthy".padEnd(9) + "=== twin");
for (const [label, make] of rows) {
  const value = unwrap(make());
  const twin = unwrap(make());
  console.log(label.padEnd(20) + (typeof value).padEnd(10) + String(Boolean(value)).padEnd(9) + String(value === twin));
}

# How a page is checked — one function, run by Node and checked by tsc

**Level:** 101 · read this before any other page

**One line:** Every output block in this library was printed by a program that CI runs on two machines: Node runs a JavaScript example, `tsc` type-checks a TypeScript example before Node runs it with its types erased, and an example meant to fail records exactly what `tsc` said.

The same small function appears three times below: once in JavaScript, once in TypeScript, and once with the call that TypeScript exists to refuse.

## The JavaScript version

<!-- source:page_check_total_js -->
*[`page_check_total_js.js`](examples/page_check_total_js.js) in full — pasted here by `tools/run_examples.py` from the file CI runs.*

```javascript
// One function, called twice: once with numbers, once with a string among them.
function total(prices) {
  return prices.reduce((sum, price) => sum + price, 0);
}

console.log(total([1999, 250, 5]));
console.log(total(["1999", 250, 5]));
```
<!-- /source -->

<!-- output:page_check_total_js -->
*Verified output of [`page_check_total_js.js`](examples/page_check_total_js.js) — regenerated by `tools/run_examples.py`, never hand-typed.*

```text
2254
019992505
```
<!-- /output -->

**Reading the output.** The first call adds three numbers. The second call has a string in first place, and JavaScript does not complain: `0 + "1999"` is the string `"01999"`, and every later `+` appends to it. The program exits normally. Why `+` turns into string concatenation is the subject of [The `+` operator](../../03_Equality_and_Coercion/the_plus_operator/README.md).

## The TypeScript version

<!-- source:page_check_total_ts -->
*[`page_check_total_ts.ts`](examples/page_check_total_ts.ts) in full — pasted here by `tools/run_examples.py` from the file CI runs.*

```typescript
// The same function with its types written down. Node erases the annotations
// and runs what is left.
function total(prices: number[]): number {
  return prices.reduce((sum, price) => sum + price, 0);
}

console.log(total([1999, 250, 5]));
```
<!-- /source -->

<!-- output:page_check_total_ts -->
*Verified output of [`page_check_total_ts.ts`](examples/page_check_total_ts.ts) — regenerated by `tools/run_examples.py`, never hand-typed.*

```text
2254
```
<!-- /output -->

**Reading the output.** The same answer as the JavaScript version's first line. Node reads a `.ts` file by erasing the annotations (`: number[]`, `: number`) and running the JavaScript that is left, so the types change nothing at run time. See [Types are erased](../../22_TypeScript_Basics/types_are_erased/README.md) and [Running TypeScript](../../22_TypeScript_Basics/running_typescript/README.md).

## The call TypeScript refuses

<!-- source:page_check_total_tserror -->
*[`page_check_total_tserror.ts`](examples/page_check_total_tserror.ts) in full — pasted here by `tools/run_examples.py` from the file CI runs.*

```typescript
// The call the JavaScript version accepted without a word. tsc refuses it
// before anything runs.
function total(prices: number[]): number {
  return prices.reduce((sum, price) => sum + price, 0);
}

console.log(total(["1999", 250, 5]));
```
<!-- /source -->

<!-- output:page_check_total_tserror -->
*What `tsc` says about [`page_check_total_tserror.ts`](examples/page_check_total_tserror.ts) — regenerated by `tools/run_examples.py`, never hand-typed.*

```text
page_check_total_tserror.ts:7:20 - error TS2322: Type 'string' is not assignable to type 'number'.

7 console.log(total(["1999", 250, 5]));
                     ~~~~~~


Found 1 error in page_check_total_tserror.ts:7
```
<!-- /output -->

**Reading the output.** This file is never run. Its stem ends in `_tserror`, so the runner passes it to `tsc` alone, requires the check to fail, and records the diagnostics as its answer key, the way a terminal shows them. Line 7, column 20 is the string `"1999"`: `tsc` rejects the call that the JavaScript version turned into `019992505`.

## How each block got here

1. The page does not contain the output as typed text. It contains a pair of markers, and the lines between them are generated:

    ```markdown
    <!-- output:page_check_total_js -->
    <!-- /output -->
    ```

2. `tools/run_examples.py` finds `examples/page_check_total_js.js`, runs it from its own folder with `node`, and pastes what it printed between the markers. `<!-- source: -->` markers paste the program itself.
3. Before running anything, the runner type-checks every TypeScript example in one `tsc` run. A type error in a `_ts` example fails the build.
4. Each output is compared with the example's recorded answer key, the `.out` file beside it. CI runs the same comparison with `--check` on Ubuntu (x86-64) and macOS (arm64), with Node 24 and TypeScript 7.0.2, so a page cannot show output that either machine would not print.

The runner fixes the environment first (`LC_ALL=C`, `TZ=UTC`, no `NODE_OPTIONS`, colours off), so an answer key depends on the program and not on whoever ran it.

## What to do

Run the examples yourself. From the repo root, after installing the pinned compiler once with `npm ci`:

```bash
python3 tools/run_examples.py --only 00_Start_Here/how_a_page_is_checked
```

Or run a single file by hand from its folder:

```bash
node page_check_total_js.js
```
